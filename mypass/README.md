# MyPass 🔑

macOS 用のシンプルなパスワード管理アプリ（SwiftUI 製ネイティブ GUI）。
サービスのログイン情報をカテゴリ分けして保存し、マスターパスワード 1 つで
まとめて暗号化・管理できます。

> ⚠️ ネイティブ macOS アプリのため GitHub Pages では動きません
> （mynetworth / myorganizer などと同じローカルビルドのツール群です）。

---

## なぜ安全なのか（セキュリティ設計）

MyPass は「**PC を物理的に盗まれ、ディスクを取り出して中身を直接読まれても、保存内容が割れないこと**」を
最優先の設計目標にしています。安全性は次の柱で担保されます。

### 1. 保存されるものは、すべて暗号化された 1 つの Blob だけ

- vault 全体（エントリー・カテゴリを含む JSON）を、ランダムに生成した 256bit の
  **データ鍵（DEK）**で **AES-256-GCM** 暗号化して保存します。
- **エントリー単位ではなく vault ファイル全体を暗号化**します。これにより、タイトルや URL などの
  **メタデータも一切平文で残りません**。盗難時に「どのサービスのアカウントを持っているか」という
  リスト自体が漏れないようにするためです。
- AES-GCM は**認証付き暗号（AEAD）**なので、暗号文が 1 バイトでも改ざんされると復号が失敗します
  （静かに壊れたデータを読むことがない）。
- ディスクを直接覗いても、`vault.dat` はランダムに見える暗号文の塊で、鍵なしには**メタデータすら**
  読めません。

### 2. エンベロープ暗号化 — マスターパスワードはどこにも保存しない

```
                          ┌─────────────────────────┐
  マスターパスワード ──PBKDF2──▶  KEK(password)  ──┐   │
                                                  ├─▶ DEK ──AES-256-GCM──▶ vault(暗号文)
  リカバリーキー ─────PBKDF2──▶  KEK(recovery)  ──┘   │
                          └─────────────────────────┘
```

- vault を暗号化する DEK は、**マスターパスワード由来の鍵（KEK）**と
  **リカバリーキー由来の鍵**の *両方* で AES-GCM ラップして保存します（エンベロープ暗号化）。
  どちらの経路でも DEK を取り出せるので、パスワードを忘れてもリカバリーキーで復旧できます。
- **マスターパスワードそのものはディスクにも Keychain にも一切保存しません。** 知っているのは
  ユーザーの記憶だけ、というゼロ知識が成立します。DEK も**アンロック中のみメモリ上に存在**し、
  ロック・終了時に破棄されます。
- **パスワード変更・リカバリーキー再生成のたびに DEK ごと作り直し**、vault を新しい鍵で
  再暗号化します（鍵ローテーション）。古いバックアップや Time Machine 内の旧 `vault.dat` を
  旧パスワード／旧リカバリーキーと組み合わせても、**現在の vault は復号できません**。
  ローテーションに伴いリカバリーキーは新しく発行され（KDF は一方向のため旧キーでは
  新 DEK を包み直せない）、Touch ID は新しい鍵に自動で貼り替わります。

### 3. 総当たり（オフライン攻撃）に強い鍵導出

- 鍵導出は **PBKDF2-HMAC-SHA256** を **600,000 回**反復（OWASP 推奨値）。パスワード 1 つの試行に
  意図的にコストをかけ、ディスクを持ち去ってのオフライン総当たりを著しく遅くします。
- ソルトは vault ごとにランダム生成（16 バイト）。レインボーテーブルや事前計算が効きません。
- 実装は **Apple のシステムフレームワーク（CommonCrypto + CryptoKit）のみ**で完結し、**サードパーティ暗号ライブラリは一切使いません**。
  素性の分からない依存を持ち込まないこと自体が、攻撃対象領域を小さく保つ設計判断です。

### 4. Kerckhoffs の原則 — ソースを読まれても鍵は割れない

- 暗号ロジックに秘密鍵をハードコードするような実装は**行いません**。ソースコードやバイナリ、
  あるいは後述のバックアップファイルを丸ごと入手されても、解析できるのは**アルゴリズムだけ**で、
  鍵そのものは導出できません。
- したがって安全性は **マスターパスワードの強度のみ**に依存します。だからこそ作成時に
  **8 文字以上**を必須化しています（強度は利用者の選ぶパスワードに委ねられます）。

### 5. 通信しない — リモート漏洩経路が存在しない

- **クラウド同期・アカウント登録・テレメトリを一切持ちません。** ネットワーク通信をしないため、
  「サーバー侵害」「通信の盗聴」「同期経由の漏洩」といった経路がそもそも存在しません。
- Time Machine 等のバックアップに乗るコピーも、暗号化済みの `vault.dat` なのでそのまま安全です。

### 6. 使用中・離席時の保護

- **自動ロック**（無操作 N 分で施錠）と、**バックグラウンド移行時の即ロック**に対応。ロックすると
  メモリ上の平文エントリーと DEK を破棄し、次回アンロック時に再復号します。
- パスワードのコピーは **30 秒でクリップボードから自動消去**（コピー後に別の内容が入っていれば
  上書きしません）。さらに `Concealed` / `Transient` マークを付け、Raycast / Maccy などの
  **クリップボード履歴アプリに残らない**ようにします。
- パスワード入力欄はフォーカス時に**自動で英数入力に固定**され、IME（全角）状態でも確実に打てます
  （入力ミスによる弱いパスワードの混入を防ぎます）。

### 守れる脅威 / 守れない脅威（正直に）

| 脅威 | 対策 |
|------|------|
| PC の物理盗難（電源 OFF / ロック画面） | ✅ 主防御。`vault.dat` の AES-256-GCM + PBKDF2 で保護 |
| バックアップファイルの流出 | ✅ 暗号文のまま。パスワードなしには復号不可 |
| ネットワーク経由の攻撃 | ✅ 通信しないため経路なし |
| オフライン総当たり | ⚠️ PBKDF2 60 万回で大幅に遅延（最終的にはパスワード強度次第） |
| 旧パスワード漏えい + 古いバックアップの入手 | ✅ 変更時の DEK ローテーションで現在の vault は守られる |
| 離席中の覗き見 | ✅ 自動ロック / 手動ロック |
| **ログイン中の同一ユーザー権限で動くマルウェア** | ❌ 防げない。アンロック中はメモリに平文があり、キーロガーやメモリ読み取りには無力 |

> **重要**: MyPass は「盗難・紛失時にデータを守る」ためのものであり、既に侵入された環境での
> 万能の盾ではありません。OS ログインパスワード・FileVault・macOS の最新化と併用してください。

## 機能

### エントリー管理
- タイトル / カテゴリ / ログイン名 / パスワード / ヒント / URL / メモ を保存
- 一覧はタイトルのみ表示（**ユーザー名は一覧に出さない**＝肩越しの覗き見対策）。詳細画面で確認・コピー
- 詳細・編集の両方で**パスワードの表示 / 非表示トグル**、ワンクリックコピー
- タイトル・ログイン名・URL で絞り込む検索

### カテゴリ
- 初期カテゴリ（Web / メール / 金融 / SNS / 仕事 / ショッピング / その他）付き
- サイドバー下部の「カテゴリを追加」から**自分でカテゴリを追加**（名前 + アイコン 28 種）
- 右クリック →「名前・アイコンを変更」で**リネーム**、「削除」で削除（「その他」は削除不可。
  削除したカテゴリのエントリーは「その他」に移動）
- **ドラッグ&ドロップで並べ替え**（順序は保存されます）

### CSV インポート
- ツールバーの ⬇（またはトップ画面のインポートボタン）でヘッダー付き CSV を取り込み。
  列名を自動判定（Chrome / Safari / 1Password / Bitwarden などの一般的なエクスポート形式に対応、
  日本語列名も可）。
- **エンコーディングを自動判定**（UTF-8 / UTF-8 BOM / Shift-JIS / UTF-16）。Excel が書き出す
  日本語 CSV（BOM 付き・CRLF 改行）もそのまま読めます。
- タイトル・ログイン名・パスワードが同一の既存エントリーは重複としてスキップ。`category` 列が
  あれば既存カテゴリに一致させ、無ければ新規作成します。
- 書き方の見本はリポジトリ同梱の [`sample-import.csv`](sample-import.csv) を参照。

> ⚠️ **CSV はインポート用の平文形式です。** エクスポート元の CSV は用が済んだら安全に削除してください
> （MyPass 自身は**平文 CSV エクスポートを提供しません** — 誤って平文パスワード一覧を作らないため）。

### 暗号化バックアップ / 復元（PC 移行にも使用）
- 設定（⚙）→「バックアップを書き出す…」で vault を **暗号化したまま** 単一ファイルに書き出します。
  ファイルは MyPass 専用形式 **`.passmanbackup`**（マジックヘッダー付き）で、中身は `vault.dat` と
  同じエンベロープ暗号化（AES-256-GCM）。**普通のテキストエディタで開いても暗号文の塊で読めず、
  他アプリでは開けません。** マスターパスワード／リカバリーキーが無ければ復号不可です。
- **復元はロック画面・作成画面からも可能**なので、新しい Mac に移行するときは初回起動画面から
  そのまま復元できます（下記「別の Mac へ移行する」参照）。
- 復元時は上書き前の状態を `vault.prerestore.bak` に自動退避します。
- バックアップにはアプリ埋め込みの秘密鍵などは一切ありません。安全性はファイル形式ではなく
  マスターパスワード／リカバリーキーによる暗号にのみ依存します（Kerckhoffs の原則）。

### ロック解除の 4 段階
1. **マスターパスワード** — 通常の解除方法
2. **Touch ID（指紋）** — 設定でオンにすると日常の解除を指紋で。パスワードを変更しても有効なまま
3. **リカバリーキー** — マスターパスワードを忘れたとき用。vault 作成時に一度だけ表示される
   25 文字のキー（例 `MVHHK-RHJA6-ANC24-XBDPW-EG9MQ`。Crockford Base32、**約 125bit の乱数**）。
   解除後は新しいマスターパスワードの設定を求められ、そのとき鍵ローテーションに伴い
   **新しいリカバリーキーが発行されます**（パスワード変更時・再生成時も同様）
4. **初期化** — マスターパスワードもリカバリーキーも失った場合の最終手段。確認語「初期化」の入力を
   必須にした上で、vault を完全削除して作り直します（**保存データはすべて失われます**）

> #### Touch ID についての注意（正直な限界）
> このアプリはローカルの ad-hoc 署名（Apple Developer Team なし）のため、
> Secure Enclave 連動の生体認証キーチェーンは entitlement 不足で使えません。
> そのため DEK は通常のログインキーチェーン（この端末のみ・iCloud 非同期）に保存し、
> 取り出し前に Touch ID を必須化する **アプリレベルのゲート**として実装しています。
> つまり生体認証は「利便性のためのアプリレベル保護」であり、Secure Enclave による
> 暗号的束縛ではありません。**強固な保護経路はマスターパスワードとリカバリーキーが担います。**

## データの置き場所

| データ | 保存先 | 暗号化 |
|--------|--------|--------|
| vault 本体 | `~/Library/Application Support/MyPass/vault.dat` | ✅ AES-256-GCM |
| Touch ID 用のデータ鍵 | **Keychain**（ログインキーチェーン、この端末のみ） | ✅ OS 管理 |
| 動作設定（自動ロック時間 / バックグラウンドロック） | `UserDefaults`（秘密情報ではない） | — |
| 旧フォーマットからの移行バックアップ | `~/Library/Application Support/MyPass/vault.pmv1.bak` | ✅ |
| 復元時に退避される直前の vault | `~/Library/Application Support/MyPass/vault.prerestore.bak` | ✅ |
| 手動の暗号化バックアップ（書き出し先はユーザー指定） | 任意の場所の `*.passmanbackup` ファイル | ✅ AES-256-GCM |

> リポジトリには vault も秘密情報も一切入りません（保存先はすべて上記のユーザー領域）。

## ビルドとインストール

```bash
cd mypass
swift run           # 開発ビルド（ウィンドウ起動）
./build_app.sh      # release ビルド + ad-hoc 署名 → MyPass.app
./install.sh        # ビルド → /Applications/MyApplications へコピー → 起動
```

アイコンは `swift make-icon.swift` で再生成（mynetworth と同じ紫グラデ背景 + 白い鍵穴シルエット）。

## 初回の使い方

1. 起動して**マスターパスワードを設定**（8 文字以上。これが唯一の防御なので**強く・使い回さない**）
2. 直後に表示される**リカバリーキーを必ず控える**（紙などパスワードとは別の安全な場所へ。
   この画面を閉じると二度と表示されません）
3. 「＋」からエントリーを追加。必要に応じてカテゴリも追加・並べ替え
4. （任意）設定（⚙）→「Touch IDで解除」をオンにすると、次回から指紋で解除できます

## 別の Mac へ移行する

1. **旧 Mac**: 設定（⚙）→「バックアップを書き出す…」→ `.passmanbackup` を書き出し、USB や
   クラウド経由で新しい Mac に渡します（ファイルは暗号化済みなので経路上も安全です）
2. **新 Mac**: MyPass を初回起動 → 作成画面の「**別のパソコンから移行（バックアップから復元）**」→
   ファイルを選び、**旧 Mac のマスターパスワード**を入力
3. 全エントリー・カテゴリ・並び順ごと復元されます（Touch ID は端末固有のため新 Mac で再設定）

## ファイル形式について

vault は現行の **PMV2**（JSON エンベロープ暗号化）で保存されます。ごく初期に作成した
**PMV1**（バイナリ）の vault は、マスターパスワードで初めて解除したときに自動で PMV2 へ移行し、
その際にリカバリーキーが一度だけ発行されます（移行前ファイルは `vault.pmv1.bak` に自動退避）。
