# MyPass 設計書（パスワード管理アプリ）

ステータス: **実装済み**（当初の設計書。実際の挙動・現状の仕様は `README.md` と
`Sources/MyPass/` が正。設計時点から変わっている箇所があるので、食い違ったら実装側を信じること
— 例: 鍵導出は本書が推奨する Argon2id ではなく PBKDF2-HMAC-SHA256 600k 回で実装している）

このリポジトリの他のネイティブ macOS ツール（mynetworth, myorganizer 等）と同じく、SwiftUI + Swift Package Manager によるローカル専用アプリとして設計する。クラウド同期・アカウント登録は行わず、**マシンから持ち出せない・ネットワークに出ない**ことを前提にすることで攻撃対象領域を最小化する。

## 1. 想定する脅威モデル

優先度順に、何から何を守るかを明確にしておく。

| # | 脅威 | 対策の要否 |
|---|------|-----------|
| 1 | **PCの物理盗難**（電源OFF/ロック画面状態で持ち去られる） | 最優先。ディスクを外して読まれても中身が割れないこと |
| 2 | **ログイン中に離席・画面を覗かれる**（ショルダーハック） | アプリ自体のロック/タイムアウトで対応 |
| 3 | ローカルで動くマルウェア/他プロセスからの読み取り | 一部は防げるが完全には防げない（後述） |
| 4 | 総当たり（オフライン）でマスターパスワードを割る | 鍵導出のコストを上げて対抗 |
| 5 | クリップボード経由の漏洩（他アプリの履歴機能など） | 自動クリアで軽減 |

**非対象（今回は狙わない）**: リモート攻撃者によるネットワーク経由の侵入対策（そもそも通信しないので該当なし）、複数端末間の同期、家族/チーム共有。

## 3. データ構造とファイルフォーマット

### 3.1 エントリーのモデル

```swift
struct Entry: Codable, Identifiable {
    var id: UUID
    var title: String        // サービス名
    var username: String     // ログイン名
    var password: String     // パスワード
    var url: String?
    var note: String?        // メモ
    var createdAt: Date
    var modifiedAt: Date
}
```

このモデル配列を JSON にシリアライズしたものが「保護対象の平文」全体になる。

### 3.2 なぜ「エントリー単位暗号化」ではなく「ファイル全体暗号化」か

- エントリー単位で暗号化すると、タイトルやURLなどのメタデータが平文のまま残りがちで、盗難時に「どのサービスのアカウントを持っているか」というリスト自体が漏れる。
- 検索・並び替えの利便性より、盗難耐性を優先する（このアプリの最優先ゴール）。
- ファイル全体を1つの暗号化Blobにすれば、**メタデータも含めて何も読めない**。デメリットは「毎回全件を復号してメモリに展開する」ことだが、パスワードマネージャーのエントリー数（数百件程度）ならコスト的に無視できる。

### 3.3 ファイルフォーマット案

```
[4 bytes] マジックナンバー "PMV1"
[1 byte ] フォーマットバージョン
[16 bytes] KDF salt
[12 bytes] AES-GCM nonce
[N bytes ] ciphertext (JSON配列 + GCMタグ)
```

保存時はテンポラリファイルに書いてから `rename()` でアトミックに置き換える（書き込み中のクラッシュでvaultが壊れるのを防ぐ）。

## 4. 暗号化設計（おすすめ）

### 4.1 鍵導出: マスターパスワード → 暗号鍵

| 選択肢 | 評価 |
|--------|------|
| PBKDF2 | CryptoKit標準にはないが `CommonCrypto` 経由で利用可 |
| **Argon2id（推奨）** | メモリハードで GPU/ASIC 総当たりに強い。1Password/Bitwardenも採用 |
| scrypt | Argon2idと同等の狙いだが業界標準は今はArgon2id寄り |

**推奨: Argon2id**。Swift向けには軽量なCライブラリ（`argon2` reference実装をSPMでラップ）を1つだけ依存追加する。パラメータ目安: memory 64MB, iterations 3, parallelism 4（Mac上でのUI操作なら1秒未満〜数秒に収まる範囲で調整し、実機でベンチマークして決める）。

### 4.2 暗号化: データ本体

- **AES-256-GCM**（CryptoKitに標準搭載、追加依存不要、認証付き暗号なので改ざん検知も同時に得られる）
- nonceは保存の都度ランダム生成（再利用厳禁）

### 4.3 マスターキーの扱い

- Argon2idで導出した鍵は**メモリ上にのみ**保持し、ロック時/アプリ終了時に確実にゼロクリアする（`CryptoKit.SymmetricKey`は内部でこれをある程度担保するが、独自バッファを使う場合は明示的に上書きする）。
- マスターパスワード自体はディスクにもKeychainにも一切保存しない（知っているのはユーザーの記憶だけ、というのがゼロ知識の要）。

### 4.3.1 セキュリティモデルの前提（Kerckhoffsの原則）

このアプリはソースコード/バイナリを丸ごと盗まれても安全であることを設計目標にする。暗号化ロジックに秘密鍵をハードコードするような実装は行わず、**安全性はマスターパスワードのみに依存**させる。ソースが読まれても解析できるのはアルゴリズムだけで、鍵そのものは導出できない。

弱点はマスターパスワードの強度そのものになるため、初期設定時に最低文字数・強度チェックを必須にする（Phase 1で対応）。より強固にする手段として「マスターパスワード＋キーファイル」の二要素方式も検討したが、運用の手間（キーファイルの保管場所を別途用意する必要がある）に見合わないと判断し、**採用しない**。マスターパスワード単体での強度確保（Argon2idのコストパラメータ + 強度チェック）で十分とする。

### 4.4 Touch ID / Secure Enclave 連携（利便性とのバランス）

素のマスターパスワード方式だけだと毎回入力が面倒になり、結局書き留める・使い回すといった別のリスクを生む。そこで:

- 初回アンロック時にマスターパスワードで復号した後、**Secure Enclaveに鍵を保存し、以後はTouch IDでその鍵を取り出す**方式（`LAContext` + Keychainの `kSecAttrAccessControl` に `.biometryCurrentSet` を指定）。
- これにより「PCが盗まれてSecure Enclaveごと持ち去られても、生体認証を突破しない限り鍵は取り出せない」という、Appleの標準的な保護に乗っかれる。
- 設定でTouch ID連携を無効化し、常にマスターパスワードのみを要求するモードも用意する（より偏執的なユーザー向け）。

**重要な設計判断**: Touch ID用にKeychainへ鍵を置くのは「PCの電源が入っていて、OSにログイン済み」の状態を前提にした利便性機能であり、「電源OFF/ロック画面状態での物理盗難」に対する主防御はあくまで vault.dat 自体の Argon2id+AES-256-GCM 暗号化である。この二段構えを明記しておく。

## 5. ロック機構・セッション管理

- **アイドルタイムアウト**: 既定5分操作がなければ自動ロック（設定で変更可）
- **バックグラウンド遷移で即ロック**: `NSApplication` のアクティブ状態を監視し、他アプリにフォーカスが移った瞬間にロック（オプション、デフォルトOFFでも良いが推奨はON）
- **スリープ/画面ロック連動**: `NSWorkspace` の `willSleepNotification` / スクリーンロック通知でロック
- ロック中はメモリ上の平文Entry配列を破棄し、次回アンロック時にvault.datから再復号する

## 6. クリップボード対策

- パスワードコピー後、既定30秒でクリップボードを自動クリア（コピーした内容が変わっていないか確認してから消す＝ユーザーが別の物を既にコピーしていたら上書きしない）
- macOSの `NSPasteboard` に `org.nspasteboard.ConcealedType` / `org.nspasteboard.TransientType` を付与し、Clipboard History系アプリ（Raycast, Maccyなど）に履歴として残らないようにする

## 7. 盗難対策のまとめ（今回のコア要件）

1. **FileVault前提にしない**: FileVaultが無効でも vault.dat 単体が Argon2id + AES-256-GCM で守られている設計にする（多層防御）。
2. ネットワーク通信を一切行わない（同期機能を持たない）ため、リモート漏洩経路がそもそも存在しない。
3. バックアップ（Time Machine等）で外に出るコピーも暗号化済みファイルなのでそのまま安全。
4. ブルートフォース対策として、Argon2idのコストパラメータに加え、**連続アンロック失敗時の指数バックオフ**（例: 5回失敗で30秒待機、以降倍々）をアプリ内に実装する（オフライン総当たりへの直接防御にはならないが、Touch ID誤操作等の運用上の保険として）。

## 8. エクスポート/バックアップ

- 設定画面から「暗号化バックアップを書き出す」機能を用意（vault.datのコピーをユーザー指定の場所へ、これも暗号化されたまま）
- 平文CSVエクスポートは**デフォルトでは提供しない**（誤操作でDesktopに平文パスワード一覧ができるのを防ぐため）。必要なら「危険性を理解した上でエクスポート」の警告文言付きで明示的操作を要求するオプション機能とする。

## 9. 依存ライブラリ（最小構成）

- **CryptoKit**（標準、AES-GCM・SHA256等）— 追加依存なし
- **Argon2** 実装1つ（SPMパッケージ、例: `swift-argon2` 系のラッパー）— 唯一の外部依存
- LocalAuthentication / Security framework（標準、Touch ID・Keychain）

これ以外は追加しない。パスワードマネージャーは攻撃対象領域を小さく保つことが最重要なので、UI以外のサードパーティ依存は極力ゼロに近づける。

## 10. UI構成（案）

- **ロック画面**: マスターパスワード入力 + Touch IDボタン（有効時）
- **一覧タブ**: 検索バー + Entry一覧（title/username表示、パスワードはマスク）
- **詳細/編集画面**: パスワード表示切り替え、コピー、強度インジケーター、パスワード生成ボタン
- **設定タブ**: マスターパスワード変更、Touch ID切り替え、自動ロック時間、クリップボードクリア秒数、バックアップ書き出し

## 11. 実装フェーズ案

1. **Phase 1（コア）**: CryptoStore（Argon2id + AES-GCM）、VaultFile読み書き、CRUD、ロック画面のみのUI
2. **Phase 2**: 自動ロック（アイドル/バックグラウンド/スリープ連動）、クリップボード自動クリア
3. **Phase 3**: Touch ID / Secure Enclave連携
4. **Phase 4**: パスワード生成機能、強度チェック、暗号化バックアップ書き出し

## 12. リポジトリ組み込み時の注意（CLAUDE.md準拠）

- `mypass/` はネイティブmacOSツール枠 → ルート `index.html`（Webランチャー）には**追加しない**
