# MyGallery

Photos.app 風のローカルフォルダ・フォトギャラリー(ネイティブ macOS)。
ライブラリへの取り込み(インポート)は一切せず、指定したルートフォルダ配下の
写真をその場で再帰スキャンして閲覧・整理する。

- Swift + AppKit(WKWebView なし・依存なし)。ローカルフォルダの閲覧・整理は
  実行時ネットワーク不要 — OneDrive共有リンクのブラウズ・スライドショー機能
  (下記)を使うときだけ通信する
- サイドバー: 画像を含むフォルダだけのツリー(枚数つき)+「すべての写真」
- サムネイルグリッド: 正方形サムネイル(EXIF 回転対応・並列生成・キャッシュ)、
  ツールバーのスライダー / ⌘+ / ⌘- でサイズ変更
- 複数選択: ⇧クリックで範囲選択、⌘クリックで個別トグル、⇧←/→/↑/↓ でキーボードから
  範囲選択、⌘A ですべて選択
- フルサイズビューア: ダブルクリック / Space / Return で開く、← → で移動、Esc で戻る
  (動画は `AVPlayerView` でそのまま再生。グリッドのサムネイルには先頭付近のフレーム+▶バッジを表示)
- 並び替え(ツールバーの並び替えアイコン、または表示 → 並び替え): 新しい順(既定)/ 古い順 / 名前順 / サイズが大きい順 / サイズが小さい順(サイズ順のときはサムネイル右下にファイルサイズを表示)/
  画質が良い順 / 画質が悪い順(ブレ・ピンボケの抽出用。選択すると未解析分をバックグラウンドで
  解析し、進捗をウインドウのサブタイトルに表示。サムネイル右下にスコアを表示 — ライブラリ内での
  相対比較用の数値で絶対的な意味は無い。「悪い順」で先頭に出てきたものをまとめて選択・ゴミ箱へ、
  という使い方を想定)
- 整理: ⌘⌫ でゴミ箱へ(確認なし即実行・Finder のゴミ箱から復元可)、Finder で表示(⇧⌘R)、
  ⌘C でコピー、グリッドから Finder / 他アプリへドラッグも可
- 回転(⌘R): 選択(またはビューア表示中)の写真を90°時計回りに回転して元のファイルへ
  直接上書き保存(EXIF の向きを画素に焼き込んでからリセット)。ゴミ箱と違い元に戻せない点に
  注意。RAW など書き込みに対応していない形式・動画は失敗として報告される
- 重複検出(⇧⌘D): ルートフォルダ全体の**写真**をスキャンし、完全一致(SHA-256)〜あいまい一致
  (dHash、厳密/標準/ゆるいの3段階)まで4段階のマッチレベルを切り替え可能(動画は対象外)
  (旧 MyOrganizer の「重複写真」ペインと同等のロジック。同ペインは MyOrganizer から
  削除済みのため、現在はこちらが唯一の実装)。「残す基準」
  (解像度が最大/ファイルサイズが最大/最新/最古)で各グループの1枚を自動選択し、
  カードをクリックしてゴミ箱行き/残すを個別調整、まとめてゴミ箱へ(確認あり・復元可)。
  グループ見出しのチェックボックスを外すと誤検出グループを丸ごと削除対象から除外でき、
  「1グループ最大N枚」の上限(既定3枚)で緩いマッチレベルによる大量削除も防ぐ
- フィルター(ツールバーの絞り込みアイコン): 日付範囲(すべて/今日/今週/今月/カスタム)、
  人物あり/人物なし、種類(イラストのみ/写真のみ)(いずれも Vision、オンデバイス・
  ネットワーク不要)を組み合わせて現在のフォルダの表示を絞り込む。
  件数表示は「表示中 / 全体」の形式。**人物/種類フィルターと画質順ソートは静止画専用** —
  動画には Vision 解析・ブレ判定を適用できないため、これらが有効な間は動画をグリッドから除外する
- 対応形式: 画像は JPEG / PNG / GIF / HEIC / WebP / TIFF / BMP / AVIF ほか、
  主要 RAW(CR2/CR3/NEF/ARW/DNG など。ImageIO がデコードできるもの)。
  動画は MP4 / MOV / M4V(AVFoundation が確実に再生できるコンテナのみ)
- 前回のルートフォルダ・並び順・サムネイルサイズは次回起動時に復元
- **OneDrive共有リンクのブラウズ**(旧MySlideshowから機能統合): サイドバー上部の
  「ローカル」/「OneDrive」切り替えで、OneDrive共有リンクの写真・動画をストリーミング
  表示できる。リンクは`+`/`−`ボタンで自由に追加・削除でき、追加時にリンク先の
  フォルダ一覧を自動取得してチェックボックスにする(年別フォルダ等を選んで
  「読み込み」)。OneDriveブラウズ中は回転・ゴミ箱・重複検出・人物/種類フィルター・
  画質順ソートは無効(いずれもローカルファイル・Vision解析が前提のため)
- **スライドショー**(ツールバーの再生アイコン、または表示 → スライドショー開始):
  現在グリッドに表示されている写真・動画(ローカルでもOneDriveでも)を自動連続再生する。
  写真は設定した秒数(既定6秒、3〜15秒)で自動的に次へ、動画は最後まで再生してから
  自動的に次へ進む。ランダム再生・時間制限(5分刻み、既定は無制限)・自動全画面の
  オン/オフを設定可能。再生中はマウスを動かすと3秒だけ前へ/一時停止・再開/次へ/終了の
  コントロールバーが現れ、動かさないと自動的に隠れる。ファイル名から撮影日を推測できた
  場合は右下に常時表示する

## Install

```bash
cd mygallery
./build.sh           # = ./build.sh install — build + /Applications/MyApplications へコピー
```

以降は Spotlight(⌘Space → "MyGallery")や Launchpad から起動。
ソースを変更したときだけ再実行する(ad-hoc codesign のローカル用アプリ)。

その他のコマンド:

```bash
./build.sh app       # build/ にダブルクリック可能な .app を作って開く
./build.sh build     # バイナリのみコンパイル
./build.sh clean     # build/ を削除
```

## Usage

ルートフォルダの指定方法(いずれか):

- ⌘O(ファイル → フォルダを開く…)
- ウインドウへフォルダをドラッグ&ドロップ
- Finder でフォルダを右クリック → このアプリケーションで開く → MyGallery

キーボード:

| キー | 動作 |
|---|---|
| Space / Return / ダブルクリック | フルサイズビューアを開く |
| ← → (ビューア内) | 前後の写真へ |
| Esc / Space (ビューア内) | グリッドに戻る(動画再生中は Space での誤操作防止のため無効 — 再生/一時停止はプレイヤーのコントロールで)。**スライドショー中は Space が一時停止/再開に変わる**、← → は前後の写真・動画へ、Esc で終了 |
| ⇧クリック | (グリッド内)クリックしたアイテムまでの範囲を選択 |
| ⌘クリック | (グリッド内)クリックしたアイテムだけを選択に追加/除外 |
| ⇧← ⇧→ ⇧↑ ⇧↓ | (グリッド内)キーボードで選択範囲を1件ずつ伸縮 |
| ⌘A | グリッド内のすべての写真を選択 |
| ⌘⌫ | 選択(またはビューア表示中)の写真をゴミ箱へ |
| ⌘R | 選択(またはビューア表示中)の写真を回転して上書き保存 |
| ⌘+ / ⌘- | サムネイルの拡大 / 縮小 |
| ⇧⌘D | 重複を検出… |
| ⇧⌘R | Finder で表示 |
| ⌥⌘S | サイドバーの表示/非表示 |

「再読み込み」(再スキャン)はショートカットなし(ファイルメニューから)。
⌘R を回転に割り当てたため。

## How it works

- スキャンは `FileManager.enumerator` によるバックグラウンド再帰列挙。隠しファイルと
  パッケージ内部(`.app` / `.photoslibrary` など)はスキップ。ファイルは一切動かさない。
- サムネイルは `CGImageSourceCreateThumbnailAtIndex`(EXIF 回転込み・最大 512px に
  ダウンサンプル)を並列 4 本の `OperationQueue` で生成し、`NSCache` に保持。
  RAW でも埋め込みサムネイルがあれば高速。
- グリッドは `NSCollectionView` + FlowLayout。セルは `CALayer.contentsGravity` の
  aspect-fill で正方形クロップ表示(ピクセル加工はしない)。
- ⇧クリック/⌘クリックは `NSCollectionView` 標準の複数選択(`allowsMultipleSelection`)
  にそのまま任せている。⇧←/→/↑/↓ によるキーボード範囲選択と ⌘A(`selectAll(_:)` の
  独自実装。`NSCollectionView` は自前実装しないと ⌘A が効かないため)は
  `GridCollectionView` 側で追加実装している。
- ビューアはグリッドに被せるオーバーレイビュー。まずキャッシュ済みサムネイルを即表示し、
  裏で最大 4096px を読み直して差し替える。
- 動画(MP4/MOV/M4V)はサムネイル生成に `AVAssetImageGenerator` を使い、先頭付近
  (長さの10%、最大1秒)のフレームを1枚だけ抜き出して画像と同じディスク/メモリキャッシュに
  乗せる(以降は写真と同じ扱い)。ビューアでは `AVPlayerView`(フル操作可能な標準コントロール
  付き)へ切り替えて実際に再生する。回転・重複検出・人物/種類フィルター・画質順ソートは
  いずれも静止画専用のロジック(`CGImageSource`/Vision ベース)で動画には適用できないため、
  対象から除外している(重複検出・回転は非対応として安全に弾かれるだけ、フィルター/ソートは
  該当条件が有効な間グリッドから動画自体を除外する)。
- ゴミ箱は `FileManager.trashItem`(システム標準のゴミ箱)なので Finder からいつでも戻せる。
- 回転は `CGImageSourceCreateThumbnailAtIndex`(`WithTransform: true`・実寸以上の
  `maxPixel`)で EXIF の向きを画素に反映したフル解像度画像を取得し、`CoreImage`
  (`CIImage.transformed(by:)`)で90°回転してから、元と同じ UTI で
  `CGImageDestination` により一時ファイルへ書き出し、`FileManager.replaceItemAt`
  で元ファイルとアトミックに差し替える。書き込み先の UTI が
  `CGImageDestinationCopyTypeIdentifiers()` に含まれない場合(RAW 等)は事前に
  失敗として弾き、元ファイルには一切触れない。回転後は `ThumbnailLoader` の
  メモリキャッシュを明示的に無効化し、`PhotoStore` 側の mtime を再取得することで
  ディスクキャッシュ(mtime をキーに含む)も自動的に再生成される。
- 重複検出はまず全写真を並列解析し、ファイルサイズ・寸法・dHash(9×8 グレースケールに
  縮小した 64bit 知覚ハッシュ)を1回だけ計算してキャッシュする。マッチレベルの切り替えは
  このキャッシュ済みデータの再グループ化だけで完結し、ファイルを読み直さない。
  「完全一致」はサイズ→SHA-256(`CryptoKit`、`FileHandle` ストリーミング読み)の二段階、
  「厳密/標準/ゆるい」は dHash のハミング距離を Union-Find でクラスタリングして
  類似画像(リサイズ/再エンコード後のコピー等)も検出する。旧 MyOrganizer(当時 Organizer)の
  `DupPhotosViewModel` と同じアルゴリズム(そのペインは MyOrganizer から削除済みで、現在は
  この実装だけが残っている。重複ロジックはアプリごとに独立実装 —
  ルート `CLAUDE.md` の方針どおりコードは共有しない)。
  dHash 計算は `kCGImageSourceCreateThumbnailFromImageAlways` でフル解像度デコードを
  強制するため、1枚あたり(特に RAW/HEIC)数十〜数百MBを消費しうる。解析の並列実行は
  `DispatchQueue.concurrentPerform` ではなく `DispatchSemaphore` で同時実行数を4に
  頭打ちにしている — 上限なしの `concurrentPerform` は、ファイル I/O でスレッドが
  ブロックすると GCD がワーカースレッドをコア数以上に増やしてしまい、フルデコードが
  大量に同時進行してメモリを枯渇させることがあった(写真1万枚規模で確認・解析中に発生)。
  グループ・カードの表示は`NSCollectionView`を使わずプレーンな`NSStackView`(グループの
  縦並び)+`CardsRowView`(グループ内カードの横並び)で組んでいるため(セルの自動再利用が
  無い)、候補が数千件規模になるとカードを全部一度に作るだけならメモリは問題にならないが、
  各カードが読み込むサムネイル画像は縦・横どちらの可視矩形(前後にバッファつき)とも交差
  するカードだけ読み込み、外れたら解放する(縦方向は`DuplicatesWindowController.
  updateVisibleThumbnails`、横方向は各`GroupSectionView`自身が横スクロール〈`hScroll`〉の
  `boundsDidChangeNotification`を監視して`updateHorizontalVisibility`で判定 —
  誤クラスタリング等で1グループが数百〜数千枚になっても、その中で実際に
  横スクロールして見えている数枚分しか保持しない)。導入前は全候補分の
  サムネイルを即時読み込み・保持していたため、重複グループ数が多い大きな
  ライブラリで数十GB規模のメモリを使うことがあった。
  グループ内のカード列(`GroupSectionView.cardsStack`)は`NSStackView`ではなく
  独自の`CardsRowView`(カードの`frame.origin`を横方向に手動で積み上げるだけの
  プレーンな`NSView`)を使っている。カードは`translatesAutoresizingMaskIntoConstraints
  = false`のままだが、親からposition〈x, y〉を拘束するAutoLayout制約は一切張らないので
  手動で設定した`frame.origin`がAutoLayoutに上書きされることはない(サイズ〈幅固定・
  高さはカード自身の内部制約由来〉だけAutoLayoutに任せる)。以前は`NSStackView`を
  使っていたが、`NSStackView`は隣接する arranged subview 間の間隔を暗黙の制約で
  管理しており、1グループの候補数(誤クラスタリング等で数百〜数千枚になり得る)に
  応じてその制約数が増える。チェックボックスのトグルや削除後の再構築でグループの
  ビューを破棄するたびに、ウインドウ全体で共有される1つのAutoLayout制約エンジンから
  これらを一括削除する処理が実機で詰まり、アプリが数分間ハングするバグの原因になって
  いた(`NSISEngine removeConstraintWithMarker`まわりでスタックする、というクラッシュ
  レポートで判明)。カードは全て固定サイズの単純な横一列なので、位置計算だけの
  プレーンな`NSView`に置き換えてAutoLayoutの制約数自体を候補数に依存させないようにした。
- フィルターの日付範囲は `PhotoItem.mtime`(ファイルの更新日時)に対する
  `DateInterval` 判定で、同期的かつ即座に効く。人物あり/なしは Vision の
  `VNDetectFaceRectanglesRequest`(顔検出)と `VNDetectHumanRectanglesRequest`
  (人体検出。顔が写っていない後ろ向き・横向きの人物も検出できる)を縮小画像
  (最大 800px)に併用してかけ、どちらかで検出できれば「人物あり」と判定する。
  結果を `(パス, mtime)` キーでメモリ内キャッシュする(`FaceCache`、ディスク永続化はしない)。
  人物フィルターを有効にしたときだけ、未解析の写真をバックグラウンドで並列解析して
  進捗をポップオーバーに表示し、完了後にグリッドへ反映する — フィルターを使わない限り
  顔検出は一切走らない。
  種類フィルター(イラストのみ/写真のみ)は `IllustrationCache` が同じ並列解析パターンで
  判定する。Vision にはこの用途専用の分類器が無いため2段階で判定する: ①
  EXIF(TIFF の Make/Model、Exif の LensModel)にカメラ由来の値が一切無ければ「非写真」候補
  とする(実カメラ写真はここでほぼ弾かれるため、大半のファイルは②を通らずに済む)、
  ② 候補だけ Vision の汎用画像分類 `VNClassifyImageRequest` にかけ、確信度0.3超の上位
  分類ラベルに illustration/cartoon/anime/comic/drawing/sketch 等のイラスト系キーワードが
  含まれれば「イラスト」と判定する。①のEXIFヒューリスティックと②のVision分類を
  組み合わせることで、②単体運用よりも実写真の誤検出を抑えている。人物フィルターと
  同様、種類フィルターを有効にしない限り判定は一切走らない。
  「特定の人物」の識別は Vision に顔認識(同一人物判定)の公開 API がなく自前での
  クラスタリング実装が必要になるため今回は対象外にした。
- 画質順ソート(良い順/悪い順)は `QualityCache` が「Laplacian分散」という無参照ブレ指標を
  `(パス, mtime)` キーでキャッシュする(Face/IllustrationCacheと同じキャッシュ・並列解析
  パターン)。長辺500pxへフルデコード縮小(埋め込みサムネイルではなく
  `kCGImageSourceCreateThumbnailFromImageAlways` で本体から再デコード)→グレースケール化→
  離散ラプラシアン(上下左右4画素との差 - 中心×4)をかけ、その応答の分散を取る。ピントが
  合ってくっきりした輪郭が多い写真ほど応答の振れ幅(分散)が大きく、ブレた写真は輪郭が
  なだらかになって分散が小さくなる。絶対的な閾値は無く、同じライブラリ内での相対比較
  (並び替え)専用。フルデコードが要る点は重複検出のdHash計算と同じ理由でメモリを
  数十〜数百MB消費しうるため、同時実行数はセマフォで4に制限している。並び替えメニューで
  画質順を選んだときだけ、未解析分をバックグラウンドで解析する(他のソート順や他の
  フィルターとは独立に、選んだときだけ走る)。

## Requirements

macOS 11+ と Swift toolchain(`swiftc`)— Xcode Command Line Tools で十分。
